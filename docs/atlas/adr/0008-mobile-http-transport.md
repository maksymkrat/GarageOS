# ADR-0008 · HTTP-транспорт мобілки й адреса API

**Статус:** Accepted · **Дата:** 2026-10-14 · **Ухвалено:** 2026-10-14

## Контекст

До цього рішення `GarageOSMobile` жив на мок-транспорті: усі шість модулів у
`src/api/` викликали `request()` з `src/api/mock/transport.ts`, який віддавав
дані з `src/api/mock/store.ts` через `setTimeout`. Сервер при цьому був
готовий — дев'ять ендпойнтів контракту плюс чотири ендпойнти входу
([04-api-surface.md](../04-api-surface.md)).

Через це два ярусы працювали, але ніколи не розмовляли: вхід у застосунку
крутив мок-коди й не створював рядка в `users`, а справжній `/auth/*` не мав
хто викликати, крім `curl`. Перевірити систему «в купі» було неможливо.

[04-api-surface.md](../04-api-surface.md#конвенції) свідомо відкладав два
питання «до появи HTTP-клієнта»:

- префікс і версія шляхів (`/api`, `/v1`) — у контракті немає ні того, ні того;
- як клієнт дізнається **адресу** сервера.

Цей ADR їх закриває, бо HTTP-клієнт з'явився.

## Варіанти для адреси

**Хардкод IP у коді.** `http://192.168.31.113:5101`. Працює рівно до
наступного перепідключення до Wi-Fi: адреса ноутбука в домашній мережі
орендована DHCP і змінюється. Кожна зміна — коміт.

**Тільки змінна оточення.** `EXPO_PUBLIC_API_URL` в `.env`. Явно, працює
однаково в усіх середовищах, але вимагає, щоб кожен розробник (і кожен, хто
клонує репо) спершу дізнався свою LAN-адресу й вписав її руками. Телефон на
тій самій Wi-Fi не працює «з коробки».

**Вивести з адреси Metro.** `Constants.expoConfig.hostUri` у dev-білді містить
`"192.168.31.113:8081"` — тобто саму адресу, якою телефон щойно
завантажив бандл. API в розробці живе на тій самій машині, тож достатньо
замінити порт. Перевірено на запущеному сервері: `hostUri` справді
заповнений. У release-білді `hostUri` відсутній.

**Service discovery (mDNS/Bonjour).** Правильно «по-дорослому», але це
залежність і код виявлення заради однієї машини в одній мережі.

## Рішення

**`EXPO_PUBLIC_API_URL`, якщо задана; інакше — хост із `hostUri` і порт
`5101`.** Реалізація — `GarageOSMobile/src/api/client.ts`.

Порядок саме такий: автовизначення прибирає конфігурацію з типового шляху
(телефон у тій самій мережі працює без жодного файлу й не ламається, коли
DHCP видав ноутбуку іншу адресу), а змінна лишається єдиним способом
дотягнутися до API, якого немає на машині розробника — staging, тунель,
емулятор з іншим хостом. Release-білд **мусить** отримати змінну на етапі
збірки, бо `hostUri` там порожній.

Порт `5101` — константа в коді, не конфігурація: він зашитий у
`GarageOS.Api/Properties/launchSettings.json`, і два місця для одного числа
розійдуться. Коли API поїде на інший порт чи за реверс-проксі, це буде
`EXPO_PUBLIC_API_URL`, а не правка константи.

**Префікс і версію шляхів не додаємо.** Контракт лишається без `/api` і `/v1`
([ADR-0002](0002-client-contract-source-of-truth.md)): додати їх означало б
правити `src/api/*` і сервер одним комітом без жодної сьогоднішньої потреби.

**`request()` лишає сигнатуру `"METHOD /path"`.** Рядок уже був канонічною
назвою ендпойнта в атласі й у `ApiError`; завдяки цьому заміна транспорту не
зачепила жодного місця виклику в екранах.

## Наслідки

**Добре.** Застосунок на телефоні бачить справжні дані з Postgres; вхід іде
через справжнього бота й створює справжню сесію. Порушення
[ADR-0002](0002-client-contract-source-of-truth.md) із шляхами входу закрите
остаточно: `src/api/auth.ts` оголошує ті самі чотири шляхи. `ProblemDetails`
мапиться в `ApiError` за правилом із
[05-cross-cutting.md](../05-cross-cutting.md) — `detail` → `message`,
`status` → `status`, `instance` → `endpoint`.

**Ціна.** Для роботи застосунку тепер потрібні **запущені** Postgres, API і
бот — раніше вистачало `expo start`. Порожня БД означає порожні екрани, тож
демо-дані треба засівати (`POST /cars` плюс SQL для того, чого ендпойнти не
створюють).

**Що стало видно.** Нормалізація, яка дублювалася на клієнті (`plate` у
верхній регістр, телефон до десяти цифр), прибрана з `src/api/cars.ts` —
сервер робить те саме в `CarService`. Поле `Car.debt` сервер не перераховує з
нарядів; у демо-даних воно виставлене руками, і це справжня прогалина
сервера, а не особливість транспорту.

**`src/api/mock/` більше ніхто не імпортує.** Доля теки — окреме рішення:
видалити чи лишити як офлайн-режим за окремим прапорцем. Поки лишається
неприєднаною.

**Сесія не переживає перезавантаження.** `refreshToken` має лежати в
`expo-secure-store` ([ADR-0007](0007-telegram-sign-in.md)), а пакет ще не
залежність, тож `POST /auth/refresh` оголошений і доступний, але його ніхто
не кличе. Окрема задача — закрита в
[ADR-0028](0028-session-lasts-a-working-day.md).
