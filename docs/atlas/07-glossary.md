# 07 · Глосарій

Ідентифікатори в коді — англійські, інтерфейс і помилки — українські. Ця
сторінка тримає відповідність між ними, щоб те саме поняття не отримало двох
назв.

## Доменні сутності

| Код | Українською | Що це |
|-----|-------------|-------|
| `ClientVehicle` | авто клієнта | картка в картотеці СТО: номер, власник, телефон, пробіг і його одиниця, статус, борг. Живе довго, між візитами. Доти звалося `Car` ([ADR-0014](adr/0014-client-vehicle-rename.md)) |
| `Order` | наряд, замовлення-наряд | один візит авто: скарга, роботи, деталі. Належить авто через `clientVehicleId`. Власного статусу й дати не має ([ADR-0017](adr/0017-order-without-own-status-and-date.md)) |
| `OrderWork` | робота | рядок наряду: опис роботи, ціна і стан оплати |
| `OrderPhoto` | фото наряду | знімок візиту: рядок у `order_photos` з цілим `id` для контракту й `uuid` для імені файла. Їх може бути кілька, вони не заміняють одне одного, і живуть на `OrderDetail`, а не на `Order` ([ADR-0027](adr/0027-order-photos.md)) |
| `OrderPart` | деталь | рядок наряду: опис, закупівельна (`buy`) і продажна (`sell`) ціна, стан оплати. Кількості немає — `sell` і є підсумком рядка ([ADR-0016](adr/0016-order-line-payment.md)) |
| `Reminder` | нагадування | що треба обслужити на конкретному авто і чи вже прострочено |
| `MyVehicle` | моя техніка, одиниця техніки | власна техніка в особистому режимі: авто, мото, будь-яка обслуговувана машина. Інший режим і інший власник даних, ніж у `ClientVehicle` |
| `LogEntry` | запис журналу | одне виконане обслуговування своєї техніки: дата, пробіг, що зроблено, витрати |

## Read-моделі

| Код | Українською | Що це |
|-----|-------------|-------|
| `ClientVehicleDetail` | картка авто | авто + усі його наряди + скільки ще авто на тому ж телефоні |
| `OrderDetail` | картка наряду | наряд разом з його авто (`order`, `vehicle`) |
| `FinanceOverview` | фінансовий зріз | показники за період + боржники + сумарний борг |
| `FinanceStats` | показники | виторг (`earned`), частка робіт (`works`), частка деталей (`parts`), кількість візитів (`visits`) |
| `ReminderItem` | нагадування (для екрана) | нагадування, вже склеєне з даними авто |
| `WorkBoardRow` | рядок дошки робіт | авто + скарга з відкритого наряду + дні очікування |
| `PaymentStatus` | стан оплати | оплачений чи ні **рядок** наряду, не наряд цілком |
| `kind` | вид техніки | «Авто», «Мото» або «Техніка». Вільний рядок, є і в `ClientVehicle`, і в `MyVehicle`. Обирає, який каталог марок показує форма; вид без каталогу лишає марку й модель вільним текстом ([ADR-0029](adr/0029-vehicle-kind-picks-the-catalogue.md)) |
| `photoId` | фото | id поточного фото машини, `uuid` або відсутній. Є і в `ClientVehicle`, і в `MyVehicle`. Сам файл лежить на диску, у теці за id тієї машини; id водночас є кеш-ключем, бо заміна фото дає новий id і новий URL ([ADR-0026](adr/0026-vehicle-photo-storage.md)) |
| `orderPaid` | оплачений наряд | на наряді не лишилося неоплачених рядків. Похідне, не поле: стан оплати живе на рядку ([ADR-0016](adr/0016-order-line-payment.md)), а `POST .../pay` перемикає всі рядки разом ([ADR-0025](adr/0025-settle-order-in-one-action.md)) |
| `orderEarnings` | заробіток | що лишається СТО з наряду: роботи повністю плюс націнка на деталях (`sell - buy`). Не **підсумок** (`orderTotals().total` — скільки винен клієнт) і не **виторг** (`FinanceStats.earned` — скільки грошей пройшло за період) |

## Статуси та перелічення

| Значення | Українською | Сенс |
|----------|-------------|------|
| `in_work` | у роботі | авто в цеху, робота йде |
| `waiting_part` | чекає деталь | робота зупинена до приходу запчастини |
| `ready` | готове | роботи завершені, авто можна віддавати |
| `has_debt` | чекаю оплату | роботи зроблені, за авто не розрахувалися. Значок стану каже «Чекаю оплату»; сама сума лишається **боргом** |
| `week` / `month` / `year` | тиждень / місяць / рік | період фінансового зрізу |
| `full` / `thumb` | повне / мініатюра | розмір фото: до 1024 px для картки, до 320 px для списку |
| `km` | км | одиниця пробігу: кілометри |
| `hours` | мотогод | одиниця пробігу: мотогодини, для техніки з лічильником годин |
| `unpaid` / `paid` | не оплачено / оплачено | стан оплати рядка наряду |
| `oil` | олива | тип запису журналу |
| `brakes` | гальма | тип запису журналу |
| `tires` | шини | тип запису журналу |
| `filter` | фільтр | тип запису журналу |
| `other` | інше | тип запису журналу |

## Поняття архітектури

| Термін | Що означає в цьому проєкті |
|--------|---------------------------|
| **Атлас** | `docs/atlas/` — карта системи: межі, домени, дані, API, рішення |
| **Контракт** | `GarageOSMobile/src/types/domain.ts` + `GarageOSMobile/src/api/*.ts`. Джерело істини для форми даних ([ADR-0002](adr/0002-client-contract-source-of-truth.md)) |
| **Шов транспорту** | функція `request()` — єдина точка, де клієнт вирішує, звідки беруться дані: мок чи HTTP |
| **Сервісний режим** | `src/app/(service)/` — екрани для СТО: дошка робіт, картотека, гроші, нагадування |
| **Особистий режим** | `src/app/personal/` — свій гараж: власна техніка та її журнал |
| **Дошка робіт** | екран `work.tsx`: активні авто, згруповані за статусом авто. Збирається на клієнті, не має свого ендпойнта |

## Терміни, яких свідомо немає

Щоб їх випадково не ввели: **пост** (робоче місце), **зміна**, **механік** як
сутність, **запис на час** (appointment), **склад** і **залишок**,
**постачальник**, **рахунок** (invoice) як окремий документ, **роль** і
**користувач**. Нинішня модель обходиться без них; якщо котресь стане
потрібним — спершу сюди, потім у код.
