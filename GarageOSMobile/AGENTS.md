# Dev loop

Metro з Fast Refresh сам доставляє кожне збереження на телефон — перезапускати
бандлер після правки не треба й шкідливо. Коли перезапуск усе ж стався
(змінився `app.json`, нова залежність, впав процес), телефон лишається на
старому бандлі: підніми `npm run dev` замість `npm start` — він перезавантажить
застосунок, щойно той під'єднається. Для вже запущеного Metro те саме робить
`npm run reload`.

# Макет оновлюється разом із кодом

Файл Figma [«Екрани застосунку»](https://www.figma.com/design/Sv2lOuZq5mY7apA41kafIT)
(`fileKey` `Sv2lOuZq5mY7apA41kafIT`) зібраний **із цього коду**, тож він —
віддзеркалення, а не джерело. Правило 8 кореневого `AGENTS.md`: правка
переноситься туди в тій самій роботі, а не «колись потім». Розійшлося — винен
макет, не код.

Переносити треба, коли змінилося те, що в макеті видно:

| Зміна в коді | Що в макеті |
|---|---|
| новий екран у `src/app/` | новий фрейм у секції свого розділу |
| перероблена розкладка екрана | той самий фрейм перемальовується |
| новий або змінений компонент у `src/components/ui/` чи `forms/` | секції «Компоненти» |
| інші значення в `src/theme/tokens.ts` | кольори й відступи в усіх фреймах |
| новий текст інтерфейсу на екрані | підпис у фреймі |

Чистий рефакторинг, перейменування файлів, зміна запитів і логіки макета не
зачіпають — тоді переносити нічого.

Секції у файлі: «Екрани · Вхід», «Екрани · Головна», «Екрани · Сервіс»,
«Екрани · Наряди», «Екрани · Мій гараж», «Діалоги», плюс дві секції
компонентів. Новий фрейм кладеться у свою секцію, а не поруч із файлом.
`app/explore.tsx` до макета не входить — це залишок шаблону Expo.

Як: Figma MCP (`.mcp.json`) — `create_session` із цим `fileKey`,
`search_design_system`, далі `use_figma`; перед `use_figma` читається скіл
`/figma-use`, перед перенесенням екрана — `/figma-generate-design`. Make-файл
(вихідний дизайн) не чіпаємо: інструменти в нього писати не вміють, та й він
первинний — історія, з якої виріс код.
