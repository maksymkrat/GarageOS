# Атлас архітектури GarageOS

Атлас — карта системи: узгоджені між собою сторінки про **межі, домени, дані,
інтерфейси та рішення** GarageOS. Він існує, щоб нову людину (чи агента) можна
було ввести в контекст за одне читання, а зміну архітектури — обговорювати
посиланням на конкретну сторінку, а не на пам'ять.

## Статус (2026-10-09)

| Ярус | Стан |
|------|------|
| `GarageOSMobile` | **Робочий прототип.** Expo Router, react-query, 5 екранів у двох режимах, повний доменний контракт у `src/types/domain.ts`, дані — з мок-стора. |
| `GarageOSWeb` | **Порожній шаблон.** ASP.NET Core 9 з `WeatherForecastController`. Доменного коду немає. |
| Персистентність | **Не обрано.** Див. [ADR-0004](adr/0004-persistence.md). |

Усе, що в атласі описано для `GarageOSWeb`, є **цільовим станом** (TO-BE).
Фактичний стан — у [08-roadmap.md](08-roadmap.md).

## Правила підтримки атласу

1. **Контракт клієнта — джерело істини.** `GarageOSMobile/src/types/domain.ts` і
   `GarageOSMobile/src/api/` визначають форму даних; атлас їх документує, а не
   переозначує. Розбіжність атласу з кодом — дефект атласу.
2. **Атлас — частина Definition of Done.** Зміна, що додає домен, сутність або
   публічний ендпойнт, змінює й відповідну сторінку в тому ж коміті.
3. **Рішення — в ADR.** Сторінки описують *стан*; причини й альтернативи живуть
   в [adr/](adr/). Сторінка посилається на ADR, не дублює його.
4. **Діаграми — текстом.** Усі схеми — Mermaid у markdown: видно в diff,
   рендерить Rider/VS Code/GitHub. Бінарних картинок в атласі немає.
5. **Одна назва — одне поняття.** Нові доменні терміни спершу в
   [глосарій](07-glossary.md), потім у код. Ідентифікатори англійські,
   пояснення українські.
6. **Не вигадувати доконаний факт.** Нереалізоване позначається `TO-BE`, а
   рішення, яке ще не ухвалене, має в ADR статус `Proposed`.
