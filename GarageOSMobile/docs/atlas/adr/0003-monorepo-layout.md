# ADR-0003 · Монорепозиторій з `GarageOSMobile` та `GarageOSWeb`

**Статус:** Accepted · **Дата:** 2026-10-09

## Контекст

Застосунок і бекенд починалися як окремі папки в різних деревах:
`D:\projects\react\GarageOS` (Expo, під git) і `D:\projects\net\GarageOS`
(.NET, без git взагалі). Контракт між ними тісний: згідно з
[ADR-0002](0002-client-contract-source-of-truth.md) зміна форми даних зачіпає
обидві сторони одночасно.

## Рішення

Один репозиторій із коренем у `D:\projects\GarageOS`:

```
GarageOS/
  GarageOSMobile/      Expo / React Native, тут же docs/atlas/
  GarageOSWeb/         ASP.NET Core 9 (GarageOS.sln, GarageOS.Api/)
  .mcp.json            MCP-сервери на весь репозиторій
  .gitignore           артефакти .NET та IDE
  garage-erd.drawio    ER-схема домену
  README.md
```

Теки названі за своїм ярусом, без проміжного `apps/`: їх лише дві, і
додатковий рівень вкладеності нічого б не дав.

Корінь git створено заново (`git init -b main`). Історію колишнього
репозиторію мобільного застосунку не переносили: у ній був єдиний шаблонний
коміт Expo без жодного remote, тож вона нічого не зберігала. Уся фактична
доробка мобілки була незакомічена й увійшла першим комітом монорепо.

`.gitignore` розділений: корневий закриває артефакти .NET та IDE,
`GarageOSMobile/.gitignore` — Node та Expo.

На корінь піднято `.mcp.json`, бо MCP-сервери (drawio, figma) мусять діяти на
обидва яруси.

Поділ `GarageOSWeb` за фічами (`Features/Cars/`, `Features/Orders/`), а не за
типами, щоб межі модулів сервера збігалися з межами модулів у
`GarageOSMobile/src/api/`. Це цільовий стан: сервер поки шаблон.

## Альтернативи

**Два репозиторії** — незалежні релізи й права доступу. Відкинуто: один
розробник, спільний цикл, а зміна контракту вимагала б двох скоординованих
PR замість одного коміту.

**Папка-контейнер із двома репозиторіями** — одна робоча директорія, але
окремі історії. Відкинуто: дає найгірше з двох світів — ні атомарності
коміту, ні справжньої незалежності.

**Проміжний рівень `apps/mobile` + `apps/api`** — звична розкладка монорепо,
нейтральна до стеку. Відкинуто на користь наявних назв теки: перейменування
зачепило б робочі каталоги обох редакторів, а виграш — косметичний.

## Наслідки

**Добре:** зміна контракту — один атомарний коміт (тип клієнта + DTO сервера
+ сторінка атласу); атлас описує систему цілком, а не один ярус.

**Ціна:** CI доведеться робити з фільтрами за шляхами, щоб збірка .NET не
запускалася на правку екрана. До появи CI це не коштує нічого.

## Що ще не піднято на корінь

Наслідок «один набір правил на обидва яруси» поки неповний:

- `docs/atlas/` лежить у `GarageOSMobile/`, хоч описує всю систему, включно з
  `GarageOSWeb`;
- `CLAUDE.md`, `AGENTS.md`, `.claude/`, `.vscode/` і `LICENSE` теж лишилися в
  `GarageOSMobile/`, тому правила для агентів і налаштування редактора діють
  лише на мобільний ярус.

Доки це не зроблено, сесію, що працює з сервером, правила мобілки не
підхоплюють.
